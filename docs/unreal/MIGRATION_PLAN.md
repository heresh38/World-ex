# Unreal Engine 5 migration — audit and plan

Status: **Stage 5 (looter systems) built** on top of stages 2-4 — `unreal/ShatteredOrbit` compiles with UE 5.8 and
its 35 automation tests pass (see its README). The game is **Shattered Orbit**. The Three.js game in this repository stays intact and playable; the Unreal
project is built beside it in `unreal/ShatteredOrbit` and takes over feature by feature. Nothing is deleted until the Unreal build
has reached parity for that feature.

## 0. Constraints to be honest about

- **Unreal cannot be built or run in the cloud container.** The container has no GPU and no engine. Unreal work is
  built and tested on the owner's PC (Windows 11, UE 5.8 from the Epic Games Launcher, Visual Studio 2022 Build Tools
  with MSVC 14.44 and the Windows SDK); a session running on that PC can compile, run the editor Python scripts
  headless and run the automation tests. Each stage ends with a checklist the owner runs in the editor.
- **Blueprints and `.uasset` files are binary** and can only be created inside the editor. They are generated by
  Unreal editor Python scripts (`unreal/ShatteredOrbit/Content/Python/*.py`, stored in Git LFS) that the owner runs once from the editor,
  or replaced with C++ + data assets created from CSV/JSON (preferred, it keeps the project text-diffable).
- **Phone play ends.** UE 5.8 with Lumen/Nanite is a desktop-class target. The Three.js build stays the playable
  prototype on iPhone and in the browser until the Unreal build overtakes it.
- **Blender stays the asset tool.** All `tools/blender/*.py` scripts gain an FBX export path (UE-friendly scale,
  orientation, smoothing groups, sockets, collision `UCX_` meshes, LODs, skeletons). The same `.blend` source feeds both
  engines, so asset work done now is not lost.

## 2. Reuse / rebuild / redesign

- **Reuse directly:** game design, story, factions, weapon archetypes and their numbers (`data.js`), loot rules,
  operation scripting (as data), all Blender scripts (+ FBX export), textures (re-baked at 2K/4K where useful).
- **Rebuild with Unreal systems:** movement, camera, combat (GAS), AI (StateTree/EQS/Mass), inventory, UI
  (CommonUI), audio (MetaSounds), streaming (World Partition), vehicles (Chaos).
- **Redesign:** the instancing/LOD code (Nanite + HLOD replace it), the custom dithered LOD fades (engine dithered LOD
  transition), the browser loading pipeline (Asset Manager), the procedural WebAudio graph (MetaSounds patches).
- **Retire:** touch controls (replaced by gamepad + mouse/keyboard; mobile is out of scope for the UE build).

    SOAI/                 (stage 3: ASOEnemy, ASOEnemyAIController, ASOEnemySpawner; later StateTree + bots)

  Content/

Multiplayer from day one: every gameplay class is written server-authoritative (replicated properties, server RPCs
for fire/reload/interact, client prediction via GAS and CharacterMovement), even while the first prototype is
single-player in "listen server" mode.

## 4. Stages and acceptance checks

1. **Audit + plan** (this document) — done when the owner agrees with it.
2. **Foundation** (done) — `.uproject`, modules, GameMode/Controller/Character/Movement/Enhanced Input, graphics
   settings backend (Scalability groups + Lumen/VSM/TSR toggles), a test map generated by an editor Python script,
   automation tests, `tools/blender/export_fbx.py`.
   *Owner check:* project opens, compiles, the test map runs, WASD/mouse/gamepad move and look, settings apply.
3. **First playable combat** (done) — the player body from `players.py` (default tactical loadout, native C++
   locomotion blend of the Blender clips), the kinetic assault rifle with its physical reload (a C++ port of
   `reload.js`: mag rock-out, spare, seat, bolt rack, posing the `mag`/`bolt` parts and the first-person arms), real
   rounds with drop, the stalker with a C++ brain (sight cone + line of sight, gunfire hearing, nav mesh chase, lunge +
   melee), GAS health / shield / damage, death and respawn, a canvas HUD. Pipeline: `tools/blender/export_unreal.sh` +
   `Content/Python/import_assets.py`. Deferred: StateTree (when the roster grows), sound + VFX (stage 4), left-hand IK
   on the third-person body. *Owner check:* shoot, reload, kill, die, respawn.
4. **Graphics + asset pipeline** (done, with substitutions) — `export_fbx.py` (cm-native skeletal files, reload parts,
   materials.json), Lumen/VSM/TSR on, post-process preset, combat effects (tracers, muzzle flash + light, sparks,
   dust, creature blood, bullet-hole decals) as a C++ instanced-card particle system instead of Niagara (Niagara cannot
   be authored headless), all sounds synthesised offline by `tools/audio/sfx_synth.py` (instead of MetaSounds),
   `SOBenchmark` (1440p on an RTX 4070 Ti: 98 fps). Still open: 2K/4K texture re-bakes, Nanite for the big kits.
   *Owner check:* profile with `stat unit` / Unreal Insights at 1440p.
5. **Looter systems** (done) — `Data/game_data.json` exported from data.js; a data asset, model, optics and the full
   reload choreography for all 22 archetypes (magazine guns, revolver, pump, bolt-action, horror biomass, energy cell
   swap) with pellets / bursts / bolts / rockets / goo (splash, acid, swarm); rolled copies (rarity, perks with their
   effects, stat rolls, names), `USOInventoryComponent` on the player state (save game, three slots, vault cap 200,
   dismantle for alloy), kill drops (credits, xp, ammo, loot cores), the reliquary reward pool, the inventory screen
   (UMG in C++). Kept in SOCombat rather than a separate SOLoot module (the weapon fires the rolled stats).
   *Owner check:* open the reliquary, switch slots, compare and equip in the inventory, play with a few archetypes.
   Follow-up (owner feedback): fingers on the grips, no shots after reloads, poison pools, one name per gun with tight
   rolls (perks are the variety; ideas in `docs/design/PERK_IDEAS.md`), new modular players (male + female Orion set)
   with armour in the inventory, and a loadout screen with the live character and rendered icons.
6. **World + missions** — VANTHOS operation level, the main city hub, one frontier world.
7. **Advanced** — remaining enemies, bosses, vehicles, streaming, dedicated-server build target.
8. **Optimisation + Steam** — Steamworks (OnlineSubsystemSteam), achievements, cloud saves, packaging, crash reports.

## 5. What the owner needs to install (once)

- Epic Games Launcher → Unreal Engine 5.8 (with "Editor symbols for debugging").
- Visual Studio 2022 (Community, or the Build Tools for command-line builds) with the C++ toolset MSVC 14.44
  (14.44.35211 or newer: UE 5.8 refuses 14.44.35210 and older) and the Windows SDK; the full IDE adds the
  "Game development with C++" workload for debugging.
- Git (+ Git LFS for `.uasset`/`.umap`/textures; `.gitattributes` is provided).
- Blender 4.x (to rebuild assets; the scripts run headless the same way as in this container).
