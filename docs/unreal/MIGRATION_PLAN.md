# Unreal Engine 5 migration — audit and plan

Status: **Stage 1 (audit + plan)**. The Three.js game in this repository stays intact and playable; the Unreal
project is built beside it in `unreal/` and takes over feature by feature. Nothing is deleted until the Unreal build
has reached parity for that feature.

## 0. Constraints to be honest about

- **Unreal cannot be built or run in the cloud container this AI works in.** The container has no GPU, the editor is
  ~100 GB, and engine downloads need an Epic account. Everything Unreal-side (C++, config, Blueprints-by-description,
  Python editor scripts) is written here **uncompiled** and must be compiled and tested on the owner's PC
  (Windows, UE 5.4+ via the Epic Games Launcher, Visual Studio 2022 with the "Game development with C++" workload).
  Each stage ends with a checklist the owner runs locally; compile errors and logs come back here to be fixed.
- **Blueprints and `.uasset` files are binary** and can only be created inside the editor. They are generated by
  Unreal editor Python scripts (`unreal/<Project>/Content/Python/*.py`) that the owner runs once from the editor,
  or replaced with C++ + data assets created from CSV/JSON (preferred, it keeps the project text-diffable).
- **Phone play ends.** UE5 with Lumen/Nanite is a desktop-class target. The Three.js build stays the playable
  prototype on iPhone and in the browser until the Unreal build overtakes it.
- **Blender stays the asset tool.** All `tools/blender/*.py` scripts gain an FBX export path (UE-friendly scale,
  orientation, smoothing groups, sockets, collision `UCX_` meshes, LODs, skeletons). The same `.blend` source feeds both
  engines, so asset work done now is not lost.

## 2. Reuse / rebuild / redesign

- **Reuse directly:** game design, story, factions, weapon archetypes and their numbers (`data.js`), loot rules,
  operation scripting (as data), all Blender scripts (+ FBX export), textures (re-baked at 2K/4K where useful).
- **Rebuild with Unreal systems:** movement, camera, combat (GAS), AI (StateTree/EQS/Mass), inventory, UI
  (CommonUI), audio (MetaSounds), streaming (World Partition), vehicles (Chaos).
- **Redesign:** the instancing/LOD code (Nanite + HLOD replace it), the custom dithered LOD fades (engine dithered LOD
  transition), the browser loading pipeline (Asset Manager), the procedural WebAudio graph (MetaSounds patches).
- **Retire:** touch controls (replaced by gamepad + mouse/keyboard; mobile is out of scope for the UE build).

## 3. Project structure (created in Stage 2)

```
unreal/<Project>/
  <Project>.uproject
  Config/  DefaultEngine.ini  DefaultGame.ini  DefaultInput.ini  DefaultScalability.ini
  Source/
    <Project>/            (primary game module: GameMode, GameInstance, PlayerController, settings)
    WXCore/               (shared types, logging, save, data assets)
    WXCharacter/          (character, movement component, look/camera, animation instance)
    WXCombat/             (GAS attribute sets, abilities, damage, weapons, projectiles)
    WXAI/                 (enemy base, StateTree tasks, perception, bots)
    WXLoot/               (rarity, perks, loot tables, inventory component)
    WXWorld/              (world settings, streaming helpers, time of day, weather)
    WXUI/                 (CommonUI widgets in C++, HUD)
  Content/
    Characters/ Player/ Enemies/ Bosses/ Weapons/ Armor/ Vehicles/ Environments/ Materials/ Textures/
    Animations/ VFX/ Audio/ UI/ Maps/ Missions/ Gameplay/ Data/  Python/ (editor import scripts)
tools/blender/export_fbx.py   (shared FBX exporter used by every asset script)
```

Multiplayer from day one: every gameplay class is written server-authoritative (replicated properties, server RPCs
for fire/reload/interact, client prediction via GAS and CharacterMovement), even while the first prototype is
single-player in "listen server" mode.

## 4. Stages and acceptance checks

1. **Audit + plan** (this document) — done when the owner agrees with it.
2. **Foundation** — `.uproject`, modules, GameMode/Controller/Character/Movement/Enhanced Input, graphics settings
   backend (Scalability groups + Lumen/VSM/TSR toggles), a test map generated by an editor Python script.
   *Owner check:* project opens, compiles, the test map runs, WASD/mouse/gamepad move and look, settings apply.
3. **First playable combat** — one player character (FBX from `players.py`), one rifle with reload montage, one enemy
   (stalker) with StateTree AI, GAS damage, death/respawn. *Owner check:* shoot, reload, kill, die, respawn.
4. **Graphics + asset pipeline** — `export_fbx.py`, 2K/4K PBR bakes, Lumen/Nanite/VSM, Niagara muzzle/impact/blood
   sets, post-process volume presets. *Owner check:* profile with `stat unit` / Unreal Insights at 1440p.
5. **Looter systems** — data assets for all archetypes, perks, rarity, inventory UI, VANTHOS reward pool.
6. **World + missions** — VANTHOS operation level, the main city hub, one frontier world.
7. **Advanced** — remaining enemies, bosses, vehicles, streaming, dedicated-server build target.
8. **Optimisation + Steam** — Steamworks (OnlineSubsystemSteam), achievements, cloud saves, packaging, crash reports.

## 5. What the owner needs to install (once)

- Epic Games Launcher → Unreal Engine 5.4 or newer (with "Editor symbols for debugging").
- Visual Studio 2022 Community, workloads "Game development with C++" and ".NET desktop development".
- Git (+ Git LFS for `.uasset`/`.umap`/textures; `.gitattributes` is provided).
- Blender 4.x (to rebuild assets; the scripts run headless the same way as in this container).
